### **Нефункциональные требования**

| **№** | **Требование**                                                                                    |
|:-----:|:--------------------------------------------------------------------------------------------------|
| 1     | Обеспечение безопасности передачи ставок, недопущение утечки данных клиентов.                      |
| 2     | Снижение нагрузки на первую линию КЦ за счёт автоматизации (минимум ручного расчёта ставок).       |
| 3     | Возможность передачи данных без API (только файл-обмен, поддержка сторонним КЦ формата Excel/CSV). |
| 4     | Регулярность обновления ставок — синхронизация каждые N минут/по расписанию                        |
| 5     | Версионирование/логирование выгрузок для аудита                                                    |
| 6     | Доступность/актуальность ставок не ниже 99,9%                                                      |
| 7     | Защищённый канал передачи файлов (например, отправка только по зашифрованной почте)                |

### **Решение**

#### **Диаграммы**

- Диаграмма контекста C4 — `Context.puml`
- Диаграмма контейнеров C4 — `Containers.puml`

#### Концепция  
- **Единый источник ставки:** Всё хранилище ставок по депозитам переводится из Excel в централизованное хранилище (минимум — в АБС/интеграционный сервис).
- **Для КЦ банка:**  
    - Актуальные ставки передаются через интеграционный слой из централизованного источника прямо в систему КЦ (через API).
- **Для партнёрского КЦ:**  
    - Партнёрский КЦ получает файл (Excel/CSV) с актуальными ставками — автоматическая выгрузка по расписанию (почта, защищённый файловый обмен).
- **Обновление ставок:**  
    - Сотрудник бэк-офиса обновляет ставки один раз в централизованной системе, и они синхронизируются с обеими КЦ.
- **Логирование:**  
    - Каждая выгрузка/обновление ставок логируется/версионируется для аудита.

#### Диаграммы  
- **Контекст**:  
    - Централизованное хранилище ставок ←(обновляет)– бэк-офис   
    - Централизованное хранилище ставок –(API)→ КЦ банка  
    - Централизованное хранилище ставок –(выгрузка файла)→ Партнёрский КЦ  
- **Компоненты:**  
    - Storage (ABS/Service)
    - Export module (выгрузка, форматирование по расписанию)
    - API для КЦ банка
    - Email отправка/шифрование файлов
    - Интерфейс КЦ банка для отображения ставок

#### Логика/выбор технологий  
- Используется существующая интеграционная платформа, дорабатывается экспорт ставок в защищённом файле (csv/xls).
- Для ночного файла — шифрованная почта, либо защищённая папка с доступом по VPN.
- Компонент API/виджет для системы КЦ банка, который всегда показывает актуальные ставки онлайн.

---

### **Альтернативы**

1. Поддерживать Excel-файл на локальных ПК и рассылать вручную  
   ● Недостатки: риск ошибки, потеря контроля версий, ручная работа, риск утечки.
2. Предоставить только печатные тарифы (PDF) для операторов  
   ● Недостатки: нельзя поддерживать онлайн-актуальность, сложна в поддержке и обновлении.
3. Сделать свой веб-портал для ставок для всех КЦ  
   ● Недостатки: сложно внедрять партнёру без допуска во внутренний контур, лишние затраты.

---

### **Недостатки и ограничения, риски**
- Риск устаревания ставок при ошибках выгрузки или задержке доставки (особенно для партнёрского КЦ).
- Передача по email требует строгой организации безопасности (шифрование, контроль получения).
- Централизованное обновление может быть сложным, если legacy-процессы не будут до конца автоматизированы.
- Не все КЦ могут сразу внедрить автоматический импорт файла — может потребоваться ручное открытие файла оператором.
