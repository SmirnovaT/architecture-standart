#### **Краткое описание архитектуры:**

- **Сайт**: фронтенд (React), бэкенд (PHP), обрабатывает заявки, интегрируется с шиной.
- **Интернет-банк**: ASP.NET MVC/SQL, видит ставки (в т.ч. персональные), инициирует заявки.
- **Интеграционный сервис/шина**: промежуточный API/очередь, маршрутизирует заявки от digital-каналов в АБС, реализует минимальную бизнес-логику и кеширует заявки для бэк-офиса.
- **АБС**: ядро автоматизации депозитов, ручная обработка менеджером; обновление ставок через внутренние процессы, временно поддерживается Excel/email.
- **Call-центр**: инициирует оформление договора по заявкам сайта, при необходимости передаёт задачу бэк-офису.
- **СМС-шлюз**: уведомления и подтверждения операций.
- **Excel/email**: ручная обработка спец. ставок на этапе MVP (оставляется временно).
- **Резервный ЦОД и отказоустойчивость**: все ключевые digital-сервисы поддерживают резервирование и горизонтальный масштаб (исключая АБС).

#### **Ключевые интеграции/команды:**

- Веб-команда (сайт), команда интернет-банка, команда интеграции (шина/очередь), команда АБС, ИТ-инфраструктура (СМС; безопасность), поддержка call-центра.
- Все данные передаются только через интеграционный слой — прямого соединения digital-каналов с АБС нет.

#### **Логика архитектуры:**
- Минимальное изменение legacy-систем, максимум переиспользования текущей инфраструктуры.
- Временное сохранение ручного Excel/email между бэк-офисами для сложных кейсов.
- Фокус на безопасности, отказоустойчивости, масштабируемости, быстроте внедрения и дальнейшей расширяемости.
- Архитектура предусматривает подготовку к событиям/очередям (Kafka, если потребуется).

### **Альтернативы**

1. **Ручная обработка заявок по email/excel (legacy вариант)**  
   *Недостатки:* высокая вероятность потерь, медленно, плохо масштабируется.

2. **Прямая интеграция digital-каналов с АБС**  
   *Недостатки*: не выдержит нагрузку, АБС — single point of failure, проблемы с доступностью и масштабируемостью; сложность поддержки, риски для всего банка.

3. **Встраивание логики обработки (в т.ч. ставок) полностью в digital-канал**  
   *Недостатки*: дублирование данных, рассогласование, невозможность для оффлайн-каналов, сложности с поддержкой.

---

### **Недостатки, ограничения, риски**
- Узким местом остаётся ручная обработка спецставок; Excel/email требует последующего вывода из архитектуры.
- Существующая версия интернет-банка и платформа ограничения — нельзя просто внедрять микросервисы и новые шины (Kafka требуется доработки).
- Отказоустойчивость АБС ограничена (нет горизонтального масштабирования).
- MVP не даёт end-to-end онлайна для новых клиентов (обязательно посещение офиса для идентификации).
- Есть риск отказа digital-каналов в случае серьёзных проблем с основной инфраструктурой (хотя и есть резервный ЦОД).
- Внесение изменений в АБС и интеграцию — зона ответственности разных команд; может вызвать сложности коммуникации, требует чёткого управления проектом.
